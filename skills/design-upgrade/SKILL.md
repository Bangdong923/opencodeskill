# Design Upgrade — 화면을 못 보는 모델의 디자인 개선

너는 결과 화면을 볼 수 없다. 그래서 세 가지로 대신한다.
1. **규칙**: DESIGN.md의 토큰 값만 쓴다. "보기 좋을 것 같다"는 추측으로 값을 고르지 않는다.
2. **숫자 점검**: audit.ps1 결과로 확인한다. 오류 0이 될 때까지 고친다.
3. **사람의 눈**: 최종 판단은 사용자가 compare.html을 열어 보고 한다. 네가 "예뻐졌다"고 단정하지 않는다.

## 도구 (경로는 설치 때 채워짐)
- 점검
  `powershell -NoProfile -ExecutionPolicy Bypass -File "{{KIT_DIR}}/scripts/audit.ps1" -Path "<html>" [-Design "<DESIGN.md>"]`
  - `-Design`을 빼면 HTML과 같은 폴더의 DESIGN.md를 자동으로 쓴다.
  - 마지막 줄 `요약: 오류 N · 경고 M`. 오류가 있으면 종료 코드 1.
- 비교 페이지
  `powershell -NoProfile -ExecutionPolicy Bypass -File "{{KIT_DIR}}/scripts/compare.ps1" -Files "<원본>,<A>,<B>" -Notes "원본,A: 방향,B: 방향" -Out "compare.html"`
  - 목록은 쉼표로 구분하므로 설명(Notes) 안에는 쉼표를 쓰지 않는다.
- DESIGN.md 틀: `{{KIT_DIR}}/templates/DESIGN.template.md`
- 방향 참고 스킬 (함께 설치됨, skill 도구로 필요한 것만 불러 읽는다)
  - `redesign-existing-projects`: 기존 페이지 점검·개선 절차
  - `high-end-visual-design`: 부드럽고 고급스러운 방향
  - `minimalist-ui`: 에디토리얼 미니멀 방향
  - `design-taste-frontend`: 전반 기준 (길다. 필요한 부분만)
  - 이 스킬들에 나오는 "스크린샷을 보고 확인" 같은 단계는 이 문서의 3단계(점검)와 8단계(사용자 확인)로 대신한다.

## 절차
1. **파악**: 대상 파일을 읽는다. 지켜야 할 것을 목록으로 적는다 — 스크립트, id, JS가 쓰는 class, 폼 name, 링크, 데이터, 문구. 이것들은 절대 바꾸거나 지우지 않는다.
2. **원본 점검**: audit.ps1을 원본에 실행하고 결과를 3~5줄로 요약한다.
3. **기준 정하기**
   - 같은 폴더에 DESIGN.md가 있으면 그것이 기준이다. 모든 시안이 같은 토큰을 쓰고, 시안끼리는 레이아웃과 위계만 다르게 한다.
   - 없으면 방향마다 `DESIGN-A.md`, `DESIGN-B.md`를 템플릿으로 만든다. 원본의 브랜드색 등 살릴 것은 반영한다. 반드시 ```tokens 블록을 채운다.
4. **텍스트 와이어프레임**: 코드 전에 시안마다 390px과 1280px에서의 배치를 글로 그린다. 볼 수 없으니 레이아웃을 머리로 먼저 확정하는 단계다.
   ```
   [390] 머리말(작은 글자) / 제목 34 / 카드 1열 / 버튼 전체폭
   [1280] 최대폭 1120 가운데 / 제목 44 / 카드 3열 / 버튼 왼쪽
   ```
5. **시안 작성**: `<이름>-A.html`, `<이름>-B.html` (필요하면 `-C`). **원본은 덮어쓰지 않는다.**
   - A: 지금 느낌을 유지하며 다듬기 (가장 안전)
   - B, C: 뚜렷하게 다른 방향 (예: 부드러운 프리미엄 / 에디토리얼 미니멀)
   - 바꾸는 것은 CSS와 레이아웃용 감싸기 요소뿐이다. 내용과 기능은 1단계 목록 그대로.
6. **재점검**: 시안마다 audit.ps1을 실행한다(`-Design`으로 그 시안의 DESIGN 파일 지정). 오류 0이 될 때까지 고친다. 남은 경고는 고치거나, 남긴 이유를 한 줄로 적는다.
7. **비교 페이지**: compare.ps1로 원본과 시안들을 묶어 `compare.html`을 만든다.
8. **보고하고 멈추기**: 아래 표를 보여주고 사용자의 선택을 기다린다.
   | 시안 | 방향 | 주요 변경 | 점검 (원본 → 시안) |
   |---|---|---|---|
   그리고 "compare.html을 브라우저로 열어서 고를 시안과 고칠 점을 알려주세요 (위쪽 버튼으로 모바일 폭도 볼 수 있어요)"라고 안내한다.
9. **마무리**: 사용자 피드백을 고른 시안에 반영 → 재점검(오류 0) → `<이름>-final.html`로 저장. DESIGN 파일을 따로 만들었다면 고른 것을 `DESIGN.md`로 저장한다.

## 화면 없이 지킬 디자인 규칙
- **색**: 중립색 몇 개 + 강조색 1개. 강조색은 한 화면에 1~2곳(주 버튼, 핵심 숫자). 본문은 순수 #000 대신 아주 짙은 회색. 대비는 본문 4.5:1, 24px 이상 큰 글자 3:1.
- **글자**: 크기는 토큰 단계만 쓴다. 본문 16~18px, line-height 1.5~1.7, 제목 1.1~1.25. 제목과 본문 크기 차이 1.5배 이상. 본문 줄 길이는 max-width 60~72ch. 글꼴 2종 이하.
- **여백**: 토큰 단계만 쓴다(4의 배수). 섹션 간격 > 카드 사이 간격 > 카드 안 간격 순서로 커야 한다 — 위계는 여백으로 만든다.
- **위계**: 화면마다 가장 중요한 것 1개. 모든 걸 강조하면 아무것도 강조되지 않는다.
- **모서리·그림자**: radius 1~2종, 그림자는 없거나 약한 1단계.
- **반응형**: viewport meta, 모바일 먼저 작성 → `@media (min-width: 768px)`로 확장. 고정 px 폭 대신 max-width와 %. 그리드는 모바일에서 1열.
- **상호작용**: 버튼·링크에 hover와 `:focus-visible`. 누르는 영역 44px 이상. transition 150~250ms, `prefers-reduced-motion`이면 끈다.
- **피할 것**: 보라-파랑 그라데이션, 이모지 아이콘, 카드 안 카드, 모든 걸 카드로 감싸기, 긴 본문 가운데 정렬, 의미 없는 장식, 같은 크기 요소만 반복되는 격자.

## 점검 스크립트의 한계 (알고 쓰기)
- 대비는 "같은 CSS 규칙의 배경, 없으면 페이지 배경" 위라고 가정한 추정이다. 부모 요소 배경, 그라데이션, 이미지 위 글자는 못 잡는다 — 이런 곳은 코드를 직접 보고 대비를 계산해 적는다.
- 외부 CSS(https://)와 JS로 넣는 스타일은 점검하지 않는다.
- 숫자가 통과해도 예쁘다는 뜻은 아니다. 그래서 8단계에서 반드시 사용자에게 보여준다.
